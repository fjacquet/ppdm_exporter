# ADR-0010 — 20.1.0 API validation of provisional mappings

Status: Accepted (findings) — fixes tracked in the implementation plan
Date: 2026-06-13

## Context

Our deserialization structs were modeled from the PPDM 19.22.0 reference and the Apache-2.0
`dell/powerprotect-data-manager` module, with every unverified field tagged `// provisional`
(ADR-0009). We now hold the authoritative **20.1.0** OpenAPI 3 specs, vendored at
`docs/swagger/`:

- `9765-20.1.0.json` — v2 API (377 paths)
- `9628-20.1.0.json` — v3 API (85 paths)
- `9627-20.1.0.json` — dpilm v1 (license/registrations) — not consumed, out of scope

Schemas were resolved by following `$ref` chains
(`paths[...].get.responses["200"].content["application/json"].schema` → `#/components/schemas/...`
→ `content.items.$ref`). Verdicts: ✅ confirmed · ❌ wrong (name/type/endpoint) ·
⚠️ no source in 20.1.0 · ➕ better field available.

## Summary of actionable findings (ranked by impact)

1. **`report` SLA RPO is silently broken.** `Job.CreatedAt`→`createdAt`, but `Activity` has
   `createTime`. `backup_jobs.created_at` is always NULL, so the RPO-compliance query
   (`migrations.sql` `j.created_at >= now() - rpo`) never matches. Same bug in the
   `activitiesPath` filter (`createdAt ge`). **❌ critical.**
2. **Health collector reads the wrong endpoint.** `/api/v3/health-entities` returns health
   *rule definitions* (`HealthEntity`: categories, healthRule, enabled — no status). Live
   status is `/api/v3/health-results` → `HealthResult{status, score, healthEntityRef}`.
   `status`/`component` never populate; `ppdm_health_entity_status` is meaningless. **❌ critical.**
3. **Copies endpoint removed.** No `GET /api/v2/copies` in 20.1.0. `report` capture fetches a
   404. Replacement: `GET /api/v2/latest-copies` (returns `Copies`, same shape). **❌ critical.**
4. **Capacity fields wrong/nested.** `mtree` and `storageSystem` byte fields don't exist as
   named; storage-system capacity is nested under `details.dataDomain`. All capacity metrics
   emit 0. **❌ high.**
5. **Activity timestamps wrong.** `startedAt`/`completedAt` absent → `createTime`/`endTime`;
   `Activity.duration` (integer seconds) is authoritative. **❌ high.**
6. **`Copy.retentionLock` type mismatch.** Spec is a string enum
   (`ALL_COPIES_UNLOCKED`/`ALL_COPIES_LOCKED`/`PARTIAL_COPIES_LOCKED`), struct is `bool` →
   unmarshal yields false always; `has_immutable` SLA rollup is wrong. **❌ medium.**
7. **`Copy.policyName` / `Copy.expirationTime` have no source.** Copy carries
   `protectionPolicy{id}` (no name) and `retentionTime`/`retierTime` (no expiration). **⚠️.**

Everything else tagged `provisional` is **confirmed** and the tag should be retired.

## Decisions required (semantics beyond mechanical renames)

- **D1 Health re-point** — move to `/api/v3/health-results`; resolve the `component` label
  (no 20.1.0 source). Affects metric labels (ADR-0006).
- **D2 Copies endpoint** — `/api/v2/latest-copies` (GET, drop-in) vs `/api/v2/copies-query`
  (POST). Recommend latest-copies (no client change).
- **D3 mtree capacity** — derive used `= total - available`; drop the logical-used metric.
- **D4 Copy absent fields** — `policyName`/`expirationTime` have no source. Drop population,
  keep columns nullable (no migration churn) vs remove columns.

## Consequences

- `grep -rn provisional internal/` shrinks to only genuinely-unverified shapes after fixes.
- Three collectors + four report DTOs change; two endpoints change; capacity reads nest.
- The `report` SLA path (RPO, immutability) was producing wrong results and is corrected.
- Specs are vendored at `docs/swagger/` so the validation surface is reproducible.

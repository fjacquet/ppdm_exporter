# PPDM 20.3.0 conformance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go test that checks every collector struct's `json` tags against the vendored 20.3.0 OpenAPI specs, plus fixes for real mismatches and an ADR.

**Architecture:** One table-driven test in `package ppdm` reflects over the six decode structs, resolves the response item schema from the spec (`$ref`/`allOf`), and reports missing fields and JSON-kind conflicts. Mismatches it finds are fixed one struct + fixture at a time (ADR-0009).

**Tech Stack:** Go 1.27, stdlib only (`encoding/json`, `reflect`), no new dependency.

**Spec:** `docs/superpowers/specs/2026-11-22-ppdm-20.3.0-conformance-design.md`

## Global Constraints

- TDD; `make ci` must pass; no inline lint/semgrep suppressions (CLAUDE.md).
- Specs: `docs/swagger/21201-20.3.0.json` (v2 API), `docs/swagger/21202-20.3.0.json` (v3 API). `21200` (v1) is not consumed.
- Test needs no network and skips nothing; load each 1.5 MB spec once per run.
- Fixing a wrong field touches one struct file + one fixture (ADR-0009). Keep `// provisional` tags honest.
- Out of scope: new metrics, dashboards, `ppdmclient`, `internal/report` DTOs.

## Review Focus

- Field declared via `allOf`/`$ref` chains (not directly in `properties`): must not false-positive.
- Schema node with `properties` but no `type`: treat as object.
- Nullable / `format: date-time` strings decode into Go `string`: compatible.
- Path with query string (`/api/v2/activities?filter=…`): strip before spec lookup.
- `health-results` lives in the v3 spec, everything else in v2: registry carries the spec per row.
- New 20.3.0 enum values (`UTS`, `POWERSCALE_UNIFIED`, `FLAT_FILE`) must pass through to label values unchanged.

## File Structure

- Create `internal/ppdm/spec_conformance_test.go` — registry, spec loader, schema walker, tests.
- Modify (only if the test reports mismatches) the struct file + `internal/ppdm/testdata/*` fixture concerned.
- Create `docs/adr/0016-20.3.0-api-validation.md`; modify `docs/adr/index.md`.

### Task 1: Conformance test

**Files:**
- Create: `internal/ppdm/spec_conformance_test.go`

**Interfaces:**
- Produces (test-package, unexported):
  - `func loadSpec(t *testing.T, file string) map[string]any` — reads `../../docs/swagger/<file>`, cached via `sync.Once`/map.
  - `func itemSchema(t *testing.T, spec map[string]any, path string) map[string]any` — strips `?query`, takes `paths[path].get.responses["200"].content["application/json"].schema`, resolves it, returns the resolved `properties.content.items` schema.
  - `func resolve(spec, node map[string]any) map[string]any` — follows `$ref` (`#/components/schemas/X`), merges `properties` of every `allOf` member recursively.
  - `func checkStruct(spec, schema map[string]any, typ reflect.Type, at string) []string` — one problem string per tag missing from the schema or kind-incompatible; recurses into nested structs and slice elements.
  - Registry `var conformanceRows = []struct{ typ reflect.Type; spec, path string }{...}` with: `activity`→21201 `/api/v2/activities`; `asset`→21201 `/api/v2/assets`; `mtree`→21201 `/api/v2/datadomain-mtrees`; `storageSystem`→21201 `/api/v2/storage-systems`; `alert`→21201 `/api/v2/alerts`; `healthResult`→21202 `/api/v3/health-results`.

- [ ] **Step 1: Write the checker self-test (fails: functions undefined)**

`TestCheckStructDetects`: build an in-memory spec/schema with properties `name: string`, `count: integer`, `tags: array of string`; assert `checkStruct` returns `nil` for a struct `{Name string "name"; Count float64 "count"; Tags []string "tags"}`; exactly one problem naming `"ghost"` for a struct with an extra `json:"ghost"` field; exactly one problem naming `"tags"` for a struct where `Tags string`. Also one case where the field lives under an `allOf` member via `$ref` → no problem.

- [ ] **Step 2: Run to verify it fails**

Run: `go test ./internal/ppdm -run TestCheckStructDetects -v` — Expected: FAIL (undefined).

- [ ] **Step 3: Implement `resolve` and `checkStruct`**

Kind map: Go `string`↔`string`; `float64`/int kinds↔`number`|`integer`; `bool`↔`boolean`; slice↔`array`; struct↔`object` (also a node with `properties` and no `type`). Skip tags `-`, `,omitempty` suffix stripped. Lenient on `oneOf`/`anyOf`/missing type (no kind complaint). Untagged fields ignored.

- [ ] **Step 4: Run self-test — Expected: PASS**

- [ ] **Step 5: Write `TestCollectorStructsMatchSpec`**

For each registry row: `t.Run(typ.Name())`, `checkStruct(loadSpec(row.spec), itemSchema(...), row.typ, row.typ.Name())`, `t.Errorf` for every problem.

- [ ] **Step 6: Run it** — `go test ./internal/ppdm -run TestCollectorStructsMatchSpec -v`. Record the output: every FAIL line is an input to Task 2. If green, Task 2 shrinks to the enum test only.

- [ ] **Step 7: Commit** — `git add internal/ppdm/spec_conformance_test.go && git commit -m "test(ppdm): conformance of collector structs vs 20.3.0 specs"`
